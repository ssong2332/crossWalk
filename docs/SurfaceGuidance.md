# 노면 안내 판정표 (B: 점자블록 따라가기 / 인도→차도 이탈)

**상태: 사용자 확정 (2026-09-30, Q1~Q4 제안안 채택), 앱 구현됨 — 설정 '노면 안내 (실험)', 기본 꺼짐. 코드: `crosswalk_app/lib/services/surface_guide.dart`.** 기준값은 추정이다(§6) — 구현 전 이벤트 단위 평가, 구현 후 실기기 조정. 태스크: `docs/Tasks.md` T104.
입력 모델: `model/crosswalk_surface_t104.onnx` (LR-ASPP MobileNetV3-Small, 224, 클래스 6).

## 금지 (다른 모든 규칙보다 우선)
- 이 표에 없는 상황에서 말하지 않는다. 표에 없는 상황이 나오면 행을 추가할지 사용자에게 묻는다.
- **횡단보도 안내가 도는 동안(분류기 위·hold) 노면 안내는 말하지 않는다.** 횡단보도 위에서는 차도 픽셀이 정상이다.
- 노면 안내가 이탈 경고(P0)를 끊거나 늦추게 하지 않는다. `docs/AudioPolicy.md`의 끊기 판정표를 그대로 따른다.
- 분할 결과 한 번만으로 말하지 않는다. 연속 확인(§2)을 통과한 변화만 안내한다.

## 1. 입력 — 분할 결과에서 무엇을 읽는가

분할 출력(224×224)의 **아래 절반**을 가로 3칸으로 나눈다. 가운데 칸은 학습 평가의 "발 앞 영역"과 같다.

| 영역 | 범위 (가로 × 세로) | 뜻 |
|---|---|---|
| **앞 (F)** | 가운데 1/3 × 아래 1/2 | 발 앞 |
| **왼쪽 (L)** | 왼쪽 1/3 × 아래 1/2 | 왼발 옆 |
| **오른쪽 (R)** | 오른쪽 1/3 × 아래 1/2 | 오른발 옆 |

각 영역에서 클래스별 **면적 비율**을 구한다. "있음" = 그 영역의 5% 이상 (학습 평가와 같은 기준).

| 값 | 정의 | 평가 근거 (test 4,718장, 앞 영역) |
|---|---|---|
| 앞 선형 있음 | F의 선형 ≥ 5% | 재현 97.7% · 정밀도 76.2% |
| 앞 점형 있음 | F의 점형 ≥ 5% | 재현 93.6% · 정밀도 84.2% |
| 앞 차도 많음 | F의 차도 ≥ 50% | 5% 기준 재현 90.4% · 정밀도 90.3% (**50% 기준은 미측정**) |
| 앞 인도 많음 | F의 인도 ≥ 50% | 5% 기준 재현 95.7% · 정밀도 91.8% (**50% 기준은 미측정**) |
| 옆 선형 있음 | L 또는 R의 선형 ≥ 5% | **미측정** |

## 2. 언제 판정하는가

| 규칙 | 값 | 근거 |
|---|---|---|
| 분할 실행 | 처리 프레임 10개 중 1번 (분류 0·5, 각도 3, 위치 7과 겹치지 않는 9번째) | 실기기 측정 빌드와 같은 배치 (T104 (5)) |
| 연속 확인 | **같은 판정이 분할 결과 2번 연속**일 때만 상태를 바꾼다 | 추정 — 한 번의 오판으로 말하지 않기 위함. 지연은 약 0.7~2초 (추정) |
| 모드 | 분류기 상태가 **none 또는 crossed**일 때만 노면 안내 활성 | 금지 규칙 2번. approach는 §3 표 참고 |

## 3. 판정표

| # | 분류기 상태 | 조건 (연속 확인 후) | 안내 | 등급 | 반복 |
|---|---|---|---|---|---|
| 1 | none / crossed | **직전 3초 안에 앞 인도 많음** → 지금 **앞 차도 많음** (인도→차도 전이) | "차도입니다" | **P0** | 전이 1회 + 앞 차도 많음이 이어지면 3초마다 (이탈 경고와 같은 박자) |
| 2 | none / crossed | 처음부터 앞 차도 많음 (전이 없음 — 골목·인도 없는 길) | "차도입니다" **1회** (Q1 확정) | P0 (1번과 같은 말·같은 뜻) | 1회. 앞 차도 많음이 3초 이상 없었다가 다시 나타나야 다시 말함 |
| 3 | none / crossed | 앞 점형 없음 → **있음** | "멈춤 블록입니다" | P1 | 1회. 앞 점형이 3초 이상 없었다가 다시 나타나야 다시 말함 |
| 4 | approach | 앞 점형 있음 | 침묵 — "앞에 횡단보도"(기존)와 겹침 | — | — |
| 5 | none / crossed | 앞 선형 없음 → **있음** (블록 위에 올라섬) | 음성 없음, 짧은 확인 진동 1회 | — | 1회 |
| 6 | none / crossed | 직전에 앞 선형 있음 → 앞 없음 + **오른쪽 선형 있음** | "점자블록 오른쪽" (Q2 확정) | P2 | 1회, 앞 선형으로 돌아오면 재무장 |
| 7 | none / crossed | 직전에 앞 선형 있음 → 앞 없음 + **왼쪽 선형 있음** | "점자블록 왼쪽" (Q2 확정) | P2 | 6번과 같음 |
| 8 | none / crossed | 직전에 앞 선형 있음 → 앞·왼쪽·오른쪽 **모두 선형 없음**이 2초 이상 | "점자블록을 벗어났습니다" | P2 | 1회 |
| 9 | 위(front/left/right) / hold | 무엇이든 | 침묵 (횡단보도 안내 우선) | — | — |
| 10 | 무판정·오류 | 무엇이든 | 침묵 | — | — |

**우선순위가 겹칠 때**: 1번(P0)은 `AudioPolicy` 끊기 판정표대로 다른 안내를 즉시 끊는다. 3번(P1)·6~8번(P2)은 무음 예산(1.5초 간격, 60초에 20초)을 따른다 — 예산에 걸리면 버린다(큐에 쌓지 않음).

## 4. 진동 (Q3 확정)

기존 패턴(`docs/AudioPolicy.md` §5): 왼쪽 이탈 ‧‧ / 오른쪽 이탈 — / 복귀 아주 짧게 1번.

| 안내 | 제안 패턴 | 이유 |
|---|---|---|
| 1·2번 차도 | 짧게 **3번** (‧‧‧) | 기존 패턴과 겹치지 않는 새 패턴 — 가장 위험하므로 음성 없이도 구분돼야 함 |
| 5번 블록 위 | 아주 짧게 1번 (복귀 패턴 재사용) | "맞게 가고 있음" 의미가 같음 |
| 3·6·7·8번 | 진동 없음 (제안) | 기존 좌/우 패턴은 "이탈 방향"을 뜻해, 블록 위치 안내에 쓰면 뜻이 반대로 읽힐 수 있음 |

## 5. 결정 기록 (사용자 확정 2026-09-30 — 모두 제안안)

| # | 질문 | 선택지 | 제안 |
|---|---|---|---|
| Q1 | 인도 없이 차도·골목을 걸을 때(전이 없음) 경고하나? | (a) 침묵 (b) 처음 1회만 "차도입니다" (c) 계속 3초마다 | **(b) 확정** — 골목 보행은 흔해서 (c)는 소음, (a)는 모르는 채 걷게 됨. 등급은 1번과 같은 P0(같은 말이라 등급을 나누면 끊기 규칙이 어긋남) |
| Q2 | 선형 블록 방향 문구 | (a) "점자블록 오른쪽" (위치) (b) "오른쪽으로" (행동, 끝 안내 B안과 같은 방식) | **(a) 확정** — (b)는 횡단보도 이탈 경고 "오른쪽으로"와 같은 말이라 헷갈림 |
| Q3 | 진동 패턴 | 위 §4 표 | **§4 확정** |

## 6. 이 문서의 값은 추정이다

50% 기준, 연속 2회, 3초 재무장, 2초 벗어남 — 전부 설계 제안이다. 앞 영역 5% 기준만 test로 쟀다.
구현 전에 test 데이터로 **이벤트 단위**(전이·등장) 재현율·정밀도를 재고, 실기기 보행으로 조정한다.

## 7. 노면 횡단보도 확인 (T125, 개발 설정 '노면 횡단보도 확인 (개발)', 기본 꺼짐)

**상태: 사용자 승인(2026-10-21 "추천대로") — 개발 설정으로 시험. 코드: `crosswalk_app/lib/services/crosswalk_surface_gate.dart`, 적용 위치 `camera_screen.dart` `_onFrame`(분류 결과가 방향 판정·피드백으로 가기 전).** 근본 대책(none 데이터 보강 + 재학습)이 나오기 전의 임시 규칙이다.

금지:
- 횡단보도 위 판정(front/left/right)과 crossed·none에는 적용하지 않는다 — approach만 낮춘다.
- 이 설정 때문에 노면 모델을 따로 켜지 않는다. 노면 판정이 없으면 approach를 그대로 두고 기록에 `na`를 남긴다.

입력: 노면 판정마다 **화면 전체**(위 절반 포함) 횡단보도(클래스 3) 픽셀 비율 = `surf.cw`. 학습 사진 분석(`train/false_approach_1021/surface_cw.csv`, cw_all)과 같은 정의다.

| # | 조건 | 결과 라벨 | 기록 `cwgate.v` |
|---|---|---|---|
| 1 | 설정 꺼짐 | 그대로 | 안 남김 |
| 2 | 분류 라벨이 approach가 아님 | 그대로 | 안 남김 |
| 2b | **T126**: 초광각 0.6배 설정 켬 또는 폰 방향 가로(`mount` landscapeTopLeft/TopRight) | approach | `skip` (`why` = wide / landscape / wide,landscape) |
| 3 | 최근 노면 판정 없음 (노면 안내·주의 구역 안내 둘 다 꺼짐, 또는 마지막 판정이 2.5초보다 오래됨) | approach | `na` (적용 불가) |
| 4 | 최근 노면 판정의 횡단보도 비율 **최대값 ≥ 1%** | approach | `keep` |
| 5 | 최근 노면 판정의 횡단보도 비율 **최대값 < 1%** | **none** ("앞에 횡단보도" 안내·approach 상태 안 나옴) | `drop` |

"최근" = 마지막 5개 노면 판정 중 2.5초 안의 것.

T126 (사용자 승인 2026-10-24) 2b행 근거: 노면 모델은 세로·1배 사진으로만 학습했다. 빌드 5c27f93 실기기 13:37:26 가로(landscapeTopRight)+0.6배에서 노면 모델이 진짜 횡단보도 줄무늬를 차도로 봐(cw 0, 차도 0.73~1.0) 규칙이 켜져 있었다면 진짜 approach를 내렸을 사례(영상 `videos/Screen_Recording_20261024_133741.mp4`, 6초 뒤 실제 진입, `train/field_1024/report.md` ⓒ). 0.6배는 실제 줌 적용 여부가 아니라 **설정**을 본다(줌이 실패해도 쉼 — 쉬면 approach를 그대로 두는 안전한 쪽).

| 값 | 근거 | 상태 |
|---|---|---|
| 1% | 학습 사진에서 cw_all ≥ 1%: approach 80.4% (209장) / front 88.4% (293) / none 4.7% (300). 줄무늬 없는 연석 none 6장은 모두 0% | 사진 단위 측정. 영상·실기기 미측정 |
| 최대값 · 5개 | 노면 판정 간격 중앙값 412ms(10/21 기록 `surf` 937건) → 5개 ≈ 2초. 같은 기록의 진짜 approach(→front) 10구간 길이 0.9~5.5초, 오인(→none) 6구간 3.3~6.8초. 한 장 실패에 흔들리지 않게 최대값을 쓰고, 직전 횡단보도 흔적이 오래 남지 않게 2초로 둔다 | 추정 |
| 2.5초 | 5개 × 0.41초 + 여유 — 노면 모델을 막 켰거나 끈 뒤 오래된 판정을 쓰지 않기 위함 | 추정 |

설계 판단 — 노면 모델을 이 설정 때문에 따로 켜지 않는다: 노면 판정은 처리 프레임 10개 중 1번이고 한 번에 p50 81ms(10/21 기록)라 상시로 켜면 배터리·발열이 늘어난다. 시험 단계에서는 사용자가 노면 안내를 켜고 나가므로(10/21 기록도 켬) 충분하다. 실기기에서 효과가 확인되면 기본 동작으로 넣을 때 다시 정한다.

부수 효과: approach가 none으로 바뀌면 노면 안내(§2 모드: none/crossed에서만 활성)와 T118 멈춤 블록 안내가 막히지 않는다 — 연석에서 "앞에 횡단보도" 대신 "멈춤 블록"이 들릴 수 있다(실기기 확인 필요).
