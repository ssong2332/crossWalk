# 오디오 우선순위 정책

사용자 확정: 2026-08-24, **T108 개정 2026-10-12**(아래 §1.1·§2·§4·§6). 구현: `crosswalk_app/lib/services/audio_policy.dart`, `feedback_service.dart`.

## 금지 (다른 모든 규칙보다 우선)
- **P0(안전 경고)를 지연·억제하지 말 것.** 무음 예산·최소 간격은 P0에 적용되지 않는다.
- 낮은 등급을 **큐에 쌓지 말 것.** 늦게 도착한 안내는 정보가 아니라 오정보다. (예외: P1은 대기 슬롯 1칸에서 TTL 3초까지만 기다린다 — §2·§4)
- 이 표에 없는 상황이 나오면 임의 판단하지 말고 표에 행을 추가할지 물을 것.

## 왜 필요한가

시각장애인은 **청각으로 교통 상황을 파악한다.** 앱이 말하는 동안 그 채널이 점유된다.
확장 후보를 모두 더하면 이탈 경고 + 경로 안내 + 신호등 + 물체 경고가 **같은 채널을 두고 경쟁**한다.

정책 도입 전 상태(2026-08-24 실측, `feedback_service.dart`):

| 항목 | 이전 동작 |
|---|---|
| 끊기 규칙 | `_speak()`가 항상 `await _tts.stop()` 먼저 → **나중에 온 말이 무조건 이김** |
| 무음 보장 | 없음 |
| 좌/우 진동 | **완전히 같은 패턴** — 방향 정보가 음성에만 존재 |

마지막 항목이 특히 문제였다. 도로 소음에 음성이 묻히면 **방향 정보가 통째로 사라진다.**

## 2. 끊기 판정표 (재생 중 ↓ / 새 요청 →)

| | P0 | P1 | P2 | P3 |
|---|---|---|---|---|
| **P0 재생 중** | 끊고 교체 | **대기** | 버림 | 버림 |
| **P1 재생 중** | 즉시 끊음 | **대기** (T108; 대체만 끊음 — §6) | 버림 | 버림 |
| **P2 재생 중** | 즉시 끊음 | 즉시 끊음 | 끊고 교체 | 버림 |
| **P3 재생 중** | 즉시 끊음 | 즉시 끊음 | 즉시 끊음 | 끊고 교체 |
| **재생 없음** | 즉시 발화 | 예산 검사 후 발화 (최소 간격이면 **대기**, T108) | 예산 검사 후 발화 | 예산 검사 후 발화 |

"P0 재생 중 + P0 요청"은 §1.1 세부 순위로 정한다.

**대기는 P1만 쓰고, 대기 슬롯은 1개다.** 더 높은 등급만 덮어쓰고, 같은 등급은 먼저 온 것을 지킨다(대체 — §6 Q3 — 일 때만 덮어씀). 슬롯이 차 있으면 새 P1은 버린다(기록 이유 `slot_full`). 단, 넣기 전에 슬롯의 항목이 TTL(§3)을 넘겼으면 먼저 치운다(`say.ttl` 기록) — 만료된 항목이 슬롯을 지키면 안 된다(10/12 기록: P0가 11초 이어지는 동안 만료된 "진입했습니다"가 "건넜습니다"를 버리게 함).
대기 항목은 **재생이 끝나고 최소 간격(1.5초)이 지난 시각**에 꺼낸다(T108 — 전에는 끝나자마자 꺼내서 최소 간격에 다시 버려졌다, 기록 L3367→L3378).

## 3. 유효기간 (TTL) — 늦으면 버림

| 등급 | TTL |
|---|---|
| P0 | 1초 |
| P1 | 3초 |
| P2 | 5초 |
| P3 | 0초 (즉시 아니면 버림) |

대기 슬롯의 항목도 TTL이 지나면 발화하지 않고 버린다. TTL은 **처음 요청 시각**부터 센다(다시 대기해도 늘어나지 않음).

## 4. 무음 보장

| 규칙 | 값 | P0 적용 |
|---|---|---|
| 발화 사이 최소 무음 | **1.5초** — P1은 버리지 않고 대기(T108 Q2), P2·P3는 버림 | **면제** |
| 60초 이동창 발화 상한 | **20초** | **면제** |

P0만 면제하는 이유: 그것만이 "지금 안 들으면 다치는" 정보다.
P0 발화 시간은 예산에 **누적되지 않는다** — 안전 경고가 이후의 안전 경고를 막으면 안 된다.

## 5. 음성을 진동으로 옮기기

음성은 희소 자원이고 진동은 상대적으로 남는다.

| 상황 | 음성 | 진동 |
|---|---|---|
| 첫 이탈 경고 | 발화 | 방향 패턴 |
| **같은 방향 3초 이상 지속** | **3초마다 1회 재발화** | 방향 패턴 재발생 |
| 반대 방향으로 바뀜 | 즉시 발화 (쿨다운 무시) | 새 방향 패턴 |
| 정상 복귀(front) | 침묵 | 짧은 확인 진동 1회 |
| none / approach | 침묵 | 없음 |

**2026-08-24 변경**: 초판은 "같은 방향 계속 -> 음성 침묵"이었다. §7에 적어둔 우려대로
첫 음성을 놓치면 방향을 다시 들을 기회가 없어지므로, **3초마다 1회 재발화**로 바꿨다
(사용자 확정). 이 값은 `feedback_service.dart`의 기존 `_cooldownSeconds = 3`과 같으므로
음성 쪽 동작은 결과적으로 이전과 같다.

간격 점증(1->2->4->8초)은 **제거했다.** 3초 재발화와 충돌한다 — 진동이 8초 간격이면
음성만 나가고 진동은 없는 구간이 생겨 두 채널이 어긋난다. 진동은 음성과 같은 3초
박자로 함께 나간다.

### 진동 패턴

| 방향 | 패턴 | 의미 |
|---|---|---|
| 왼쪽 | 짧게 **2번** (‧‧) | 왼쪽으로 벗어남 |
| 오른쪽 | 길게 **1번** (—) | 오른쪽으로 벗어남 |
| 정상 복귀 | 아주 짧게 1번 | 돌아옴 |

짧은 진동 = 설정된 진동 길이의 1/4 (하한 80ms), 긴 진동 = 설정값 그대로.
사용자가 설정에서 진동 길이를 바꾸면 두 패턴이 함께 비례한다.

### 반복 간격

같은 방향이 계속되면 **3초마다** 방향 패턴을 다시 낸다. 음성 재발화와 같은 박자다.
방향이 바뀌거나 정상으로 복귀하면 즉시 낸다.

## 7. 해소된 우려 (2026-08-24)

초판에는 **"지속되는 이탈에서 음성이 영구히 침묵한다"**는 미해결 우려가 있었다.
같은 방향이 계속될 때 음성이 첫 1회뿐이면, 사용자가 그것을 놓쳤을 때
(도로 소음, 통화 중, 이어폰 미착용) 방향 정보를 다시 들을 기회가 없다.

**해소**: 3초마다 1회 재발화로 확정했다(사용자 결정). 5절 표에 반영되어 있다.

남는 판단: 3초가 적절한 간격인지는 실기기 보행 테스트로 확인해야 한다.
너무 짧으면 청각 채널을 과도하게 점유하고, 너무 길면 놓친 안내를 늦게 받는다.

## 8. 이 문서의 값들은 추정이다

1.5초, 20초/60초, 진동 패턴, 점증 간격 — 전부 실측이 아니라 설계 제안이다.
**실기기에서 걸으며 조정해야 한다.** 조정 결과가 나오면 이 문서를 갱신하고
그 근거(무엇을 어떻게 쟀는지)를 함께 적을 것.
