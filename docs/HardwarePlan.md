# HardwarePlan — 전용 하드웨어 1단계 계획

Owner: planner (see AGENTS.md). 결정은 사용자 확정(2026-10-12 대화, A안 2026-10-29 — §0). 수치 중 "추정" 표시는 미검증.

## 금지
- 단계 통과 조건을 확인하지 않고 다음 단계로 넘어가지 않는다.
- H1(A안에서는 A0·A2)에서 USB 카메라가 인식되지 않으면 별도 라이브러리·무선 전환 등 우회를 **임의로 하지 않는다** — 대안과 비용을 보고하고 결정을 받는다.
- 실사용자 체험(H6, A안에서는 A5)은 §7 안전 수칙 없이 하지 않는다.
- 고장(카메라·진동·헤드폰 끊김)을 조용히 넘기지 않는다 — 침묵은 사용자에게 "정상"으로 읽힌다.

## 3. 화각 계산 (추정 — 핀홀·평지·왜곡 없음, 가슴 높이 1.3m, 아래 기울기 30°)

| 카메라 | 가장 가까운 지면 | 폭 @1m | 폭 @2m | 폭 @3m |
|---|---|---|---|---|
| 폰 세로 (가로 50°, 추정) | 0.7m | 1.4m | 2.2m | 3.0m |
| 폰 가로 (가로 65°, 추정) | 0.9m | 1.9m | 3.0m | 4.1m |
| 광각 90° | 0.6m | 3.0m | 4.8m | 6.5m |
| 광각 120° | 0.3m | 5.3m | 8.3m | 11.3m |

- 횡단보도 폭 4m 이상(`docs/PRD.md:40`) → 중앙에서 2m 앞 양쪽 경계가 보이려면 약 90° 이상.
- **정정 (2026-10-12):** 경계가 필요한 것은 **위치(끝) 판정**이다. 방향(틀어짐) 판정은 줄무늬 기울기로 하며 경계가 필요 없다(`docs/CaptureGuide.md:30-56`, 방향 정확도 91.2%). 위치 모델 끝 재현은 왼끝 65.8%·오른끝 52.9%로 목표 70% 미달(`docs/Tasks.md` T98). 따라서 H0의 질문 = "광각이 위치 판정을 올리는가, 그 대가로 방향 판정을 떨어뜨리지 않는가"(가로·광각은 앞쪽 깊이를 잃어 기울기 판독에 불리할 수 있음, `docs/CaptureGuide.md:99-101`).
- 갤럭시 S 초광각은 보통 대각 120° 표기 → 가로 약 108°(추정). 폰으로 재현되는 상한은 120°가 아니라 약 108°. 실측은 H0 체크리스트의 화각 재기.
- 기울기 20°·45°에서 폭은 ±10% 안팎. 기울기는 주로 가장 가까운 지면을 바꾼다.
- 120°의 대가(추정): 어안 왜곡, 224px 입력에서 줄무늬 축소 → 기존 데이터와 격차 커짐.
- 하드웨어는 가로 장착도 선택 가능(PRD §제품 형태).

## 4. 1단계 시스템 구성

```
[가슴 하네스]
  ├ USB 광각 카메라 ───────USB-C────────────┐
  ├ 진동 모듈: BLE 마이컴 + 배터리           │
  │    ├ 왼쪽 어깨끈 모터                    │
  │    └ 오른쪽 어깨끈 모터 ◀─BLE─ 진동 명령 ┐│
  └ (폰 주머니)                              ││
[폰: 기존 앱] 카메라 → 판정(모델 4개) → 오디오 정책
                                     └─BT─▶ [골전도 헤드폰] 음성
```

| 앱 부분 | 지금 | 1단계 |
|---|---|---|
| 카메라 입력 | 폰 후면 카메라 | 외부 USB 카메라 (인식 여부 미검증 → H1) |
| 진동 | 폰 진동 리듬 | BLE 명령 → 가야 할 쪽 모터 + 리듬 |
| 음성 | 폰 스피커 | 변경 없음 (안드로이드 BT 오디오 라우팅) |
| 기록 (T106) | 있음 | BLE 진동 명령·연결 상태 항목 추가 → 지연 실측 |

진동 모듈: 마이컴은 BLE 지원 소형 보드(예: ESP32-C3 또는 nRF52 계열, 미정). BLE인 이유 — 폰 USB-C 단자는 카메라가 사용.

### 고장 시 동작

| 고장 | 동작 |
|---|---|
| USB 카메라 빠짐 | 안내 중단 + 음성·진동으로 "카메라 연결 끊김" (P0) |
| 진동 모듈 BLE 끊김 | 폰 진동 리듬으로 자동 대체 + 음성 1회 알림 |
| 골전도 헤드폰 끊김 | 폰 스피커로 전환(추정 — 안드로이드 기본 동작, 확인 필요) + 음성 1회 알림 |

### 제약
- 사용 중 폰 충전 불가(USB-C 점유), 카메라 전원도 폰 배터리 → 사용 시간 실측 필요.
- 현재 모델 4개는 폰 세로 사진으로 학습 → 광각에서 정확도 하락 가능(추정). H0에서 먼저 측정.

### 9-3. 고려 사항
- **추천: IMX708 광각 계열.** 1단계에서 모은 데이터가 2단계 기기(라즈베리파이급 보드)로 가장 덜 버려진다. 2단계 부품도 가장 싸다. 폰 초광각(가로 약 108°, 추정)과 화각이 비슷해 H0 결과를 옮겨 적용하기 쉽다.
- 약점(추정): IMX708은 STARVIS(IMX291/462)보다 화소가 작아 야간에 불리할 수 있다. 야간은 v1 범위(T37). H5 현장 시험에서 야간 1회 이상 확인한다.
- 양산 단가: 최종 기기는 USB 모듈이 아니라 MIPI 카메라 모듈을 보드에 직접 붙이는 형태가 된다(추정). 대량 단가는 이번 조사 범위 밖이라 모듈 업체 견적이 필요하다. IMX708·IMX462처럼 흔한 센서를 고르면 공급처 선택지가 넓다(추정).

### 9-5. 대안 — 폰 자체를 가슴에 다는 1단계
