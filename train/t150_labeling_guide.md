## 키
| 키 | 동작 |
|---|---|
| 마우스 드래그 | 선 긋기 (시작점 → 끝점 방향) |
| Enter / Space | 저장하고 다음 장 (선이 없으면 저장 안 됨) |
| S | 건너뛰기 (비스듬한 횡단보도, 안 보임, 애매함) |
| Z | 직전 장으로 돌아가기 (그 장의 라벨 줄이 지워짐, 다시 그으면 됨) |
| R | 지금 선 지우고 다시 긋기 |
| Q | 종료. 다시 실행하면 안 한 장부터 이어서 |

## 선 긋는 규칙 (사용자 확인 2026-10-28)
| 항목 | 규칙 |
|---|---|
| 무엇을 긋나 | **줄무늬 방향** (기존 라벨과 같은 기준) |
| 비스듬한 횡단보도 | **S** (건너뛰기) |
| 기준 | 사진에 보이는 그대로(카메라 기준). 원근을 머릿속으로 보정하지 않는다 |
| 각도 | 화면 위쪽 = 0°, 시계방향 = +, 반시계방향 = − (왼쪽 위 노란 숫자) |
| 사진 방향 | 도구가 시계방향 90° 돌려 세로로 보여 준다. 저장 좌표도 이 화면 기준 (T94와 같음) |
| 모델 예측 | 화면에 보여 주지 않는다 (예측에 끌려가지 않게) |

| 날짜 폴더 | 중간 (예측 12~30°) | 작음 (<12°) | 큼 (≥30°) | 계 |
|---|---|---|---|---|

| frames_1026 | 54 | 17 | 18 | 89 |

| **합계** | **230 (56%)** | **124 (30%)** | **59 (14%)** | **413** |
- **680 → 413으로 줄인 이유:** 1초 1장이라 3초 이내 사진은 거의 같은 장면이다. 이 중복을 피하려고 3초 간격을 지키면, 시범 50장과 그 앞뒤를 뺀 남은 후보에서 최대 440장만 뽑을 수 있다.
- 왜 중간 위주 + 양쪽도 섞나: 시범에서 모델이 '중간'으로 예측한 39장의 라벨은 중간 19 / 직진 10 / 큰 10이었다. 예측 구간이 정답과 크게 달라서, 직진·큰 예측 안에도 실제 중간 각도가 숨어 있을 수 있다.
- 목표는 중간 230 · 작음 95 · 큼 95였다. '큼' 예측 사진은 대부분 '중간' 사진 바로 옆(3초 이내)에 있어서 59장만 남았다. 모자란 몫은 남은 후보로 채웠고, 그렇게 채운 29장은 모두 '작음'이다.
- 고른 방법: `train/t150_select_main.py` (seed 150, 재실행 결과 동일). 구간별 몫을 폴더 후보 수에 비례해 나누고, 폴더 안에서는 횡단 묶음을 돌아가며 뽑았다. 시범 50장과 겹치는 사진은 0장이고, 시범 포함 최소 간격은 3.0초다.
