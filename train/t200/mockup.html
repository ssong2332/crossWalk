T200 횡단보도 경계 표시 시안 — 로컬 전용

거리 사진이 들어 있다. 외부(Artifact·클라우드 등)에 올리지 말 것. 이미지(img/)는 커밋하지 않는다 — PYTHONIOENCODING=utf-8 python train/t200/mockup.py로 다시 만든다(필요: 메인 체크아웃의 train/frames_*).

1. 무엇을 그렸나

  • 노면 분할 모델: 앱과 같은 crosswalk_app/assets/model/crosswalk_surface.onnx, 같은 전처리(세로 프레임 전체를 224×224로 누름, ImageNet 정규화). 클래스 3(횡단보도)의 argmax 마스크.
  • 위치 막대: 앱과 같은 crosswalk_position.onnx 한 장 출력(평활 없음). -2 왼쪽 끝 ~ +2 오른쪽 끝, 눈금은 끝 판정선 ±1.0(direction_resolver.dart:192). 흰 고리 = 끝 구간(색 아님).
  • 프레임의 실제 상태(분류기·각도)는 이 시안에 쓰지 않았다. 행 제목은 화면 모양만 적은 것이다.

2. 시안 (열: 원본 / A 칠하기 / B 외곽선 / C 칠하기+보이는 경계+위치 막대 / C 저시력 색)

3. 후보 비교

A 마스크 반투명 칠하기B 마스크 외곽선(다각형)C 옅은 칠하기 + 보이는 양 끝 경계선 + 위치 막대 (추천)
데이터 출처노면 모델 argmax==3 (이미 SurfaceFeatures.fromLogits가 224×224 전부 argmax함)같은 마스크 → 가장 큰 덩어리 → 외곽 추적·단순화같은 마스크 → 행마다 왼/오른 끝 → 직선 2개 맞춤. 위치는 기존 위치 모델(_positionSmoother 값)
떨림 처리2.5Hz 갱신이라 칸이 '툭툭' 바뀜. 최근 2~3장 마스크 다수결 또는 페이드(추정)모양(꼭짓점 수)이 매번 달라 평활이 어렵다 — 가장 많이 떨림(추정)선 끝점 4개를 EMA(기존 각도 스무더와 같은 방식) + 220ms 보간(화살표와 같음). 선 2개라 평활이 쉬움
성능(추가분)마스크 224×224 바이트 보관 + 화면에 이미지 1장 그리기(작음, 추정)Dart로 외곽 추적 구현 필요(코드량 큼), 계산은 작음(추정)argmax 루프 안에서 행별 최소/최대 x만 기록 → 직선 맞춤 224점: 1ms 미만(추정)
가슴 고정에서 보이는 모양원근 때문에 사다리꼴, 줄무늬 사이 아스팔트까지 채워져 '띠'로 보임(시안 1행)가림·그림자·차량 따라 들쭉날쭉(시안 2~4행)사다리꼴의 두 옆변. 화면 밖 경계·발 앞까지 안 온 횡단보도는 선 생략 → 틀린 선을 덜 그림
사용자 위치·이탈 방향따로 없음(칠한 띠가 화면 어디 있는지로 짐작)따로 없음아래 막대에 위치 점, 끝 구간이면 점에 고리·가까운 쪽 경계선이 굵은 이중선
실패 모습오검출이 그대로 보임 — 개발 확인엔 오히려 장점오검출이 '확실한 선'처럼 보임가림 선을 경계로 오인(3행). 경계가 안 보이면 선이 없다는 점을 사용자가 알아야 함

추천: C (동행자·개발용 보라, 기본 꺼짐 설정, 6절 규칙대로 상태별 표시) — 칠하기(A)를 옅게 깔아 모델이 본 영역을 그대로 보이되, '경계'는 확실히 보이는 옆변만 직선으로 그리고, 위치는 이미 검증된 위치 모델에서 가져온다. B는 떨림·오인이 가장 크고 구현량도 커서 제외.
