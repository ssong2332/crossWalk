# T159 보고서 — 사진만으로 이탈 단계를 가르는 각도 모델

### 결론: fullbw224(순서형, 시야 = 화면 전체, 큰 각 가중·반전 일관성)가 2단계 B=27.5·좌우반전 TTA에서 판정표를 통과했다. 단일 추론은 미달이다. 앱 입력이 바뀌고(cropRatio 1.0), PC 1스레드 시간이 기준을 약간 넘는다(T103의 2.03~2.18배, 기준 2배 — **초과**).

| 항목 | 결과 | 이전/기준값 | 근거 |
|---|---|---|---|
| 전체 1,331장 직진/약/강 재현 | 83 / 73 / 87% | 기준 ≥80(T103 직진) / ≥70 / ≥80 | `train/t159/metrics.md` 요약 fullbw224 회귀부호 반전 TTA B=27.5 |
| T150 304장 직진/약/강 재현 | 82 / 73 / 81% | 같음 | 같음 |
| 강→직진 (전체 / T150) | 0.2% / 0.0% | ≤3% | 같음 |
| 반대 방향 후보 / T103 | 전체 3 / 4, T150 1 / 3 | T103 이하 | 같음; T103 값 `train/t159/deployed_pred_all.csv` |
| 같은 후보 단일 추론 | 전체 81/67/86, T150 79/70/81 → 미달(전체 약, T150 직진) | — | 같은 표 단일 행 |
| PC 1스레드(onnxruntime, 중앙값) | 반전 포함 1파일 7.06 / 7.18 / 7.41ms | T103 같은 회차 3.47 / 3.29 / 3.49ms, 기준 6.62ms(3.31×2) | `train/t159_check_final.py`, 3회 |
| 3단계 12/20/30 | 모든 후보 미달(1·2단계 재현 41~67%) | 각 ≥70% | `metrics.md` |

### 문제/다음 단계
- **반전 TTA만 통과**: 폰 추론이 2회 분량이다. 시간은 고정 기준 6.62ms보다 7~12%, 같은 회차 T103의 2배보다 2~9% 길다(초과 표시). 채택 여부는 사용자 결정.
- **경계 B는 같은 데이터로 고름**: 예측 문턱은 나머지 fold로 골랐지만, B(20~30 중 5개)는 결과를 보고 골랐다. fullbw224는 B=27.5에서만 통과(B=25: T150 직진 78, B=30: T150 강 79). 여유도 얇다(T150 강 81, 직진 82).
- **앱 변경 필요(T160)**: cropRatio 0.778 → 1.0, 모델 교체, 출력 문턱 약 8.5° / 강 29°. 반전·평균은 ONNX 안에서 하므로 앱 로직은 없음.
- 반대 방향 오판(ord224) 11장은 모두 모델 오류였다. 최종 모델도 학습한 사진에서 전체 5장이 남는다(학습 데이터라 판정 비교용 아님).

## 1. 판정 정의 (오케스트레이터 확정표)

| 안 | 통과 조건 |
|---|---|
| 공통 | 정답 = 기하각, 직진 = \|정답\| < 12°. 직진 재현 ≥ T103(T150 80%). 반대 방향(정답 \|각\| ≥ 12, 예측 단계 ≥ 1, 부호 다름) ≤ 같은 세트의 배포 T103(전체 4, T150 3). PC 1스레드 ≤ T103 3.31ms × 2(넘으면 표시). 전체와 T150 둘 다 통과해야 통과. |
| 3단계 (12/20/30) | 1·2·3단계 재현 각 ≥ 70%, 건너뜀(직진→3, 3→직진) 각 ≤ 3% |
| 2단계 (약 12~B / 강 ≥ B, B ∈ 20~30) | 강 재현 ≥ 80%, 약 재현 ≥ 70%, 강→직진 ≤ 3% |

- 예측 문턱: fold k는 나머지 4 fold에서 (전체·T150 여유의 최솟값)이 가장 큰 문턱을 쓴다(`t159_level_eval.nested`).
- fold·정답: T151과 같다(기존 1,027장 세션 60초·근사중복 5 fold, T150 304장 묶음 30개 5 fold). 자기 라벨 없음.
- 배포 T103 반대 방향 4장 중 1장은 T103이 학습한 기존 사진이다(기준값을 그대로 씀).

## 4. 최종 모델과 폰 입력 명세

| 항목 | 값 |
|---|---|
| 학습 | 1,331장 전량, `python train/t159_train.py final fullbw224 --img 224 --threads 6 --crop 1.0 --cons 0.5 --bigw 2 --big_deg 25` (`train/t159/run_final.sh`) |
| 넘길 파일 | `model/t159/fullbw224_ord_reg_tta.onnx` (git 제외), `python train/t159_export_tta.py fullbw224` |
| sha256 | `80f06d0b1cb9554ecc87be98de27ca1b0991d32875a4499c82ea8a477b78faed` |
| 형식 | ONNX IR 7, opset 12, 입력 `input` [1,3,224,224] float32, 출력 `output` [1,1] |
| 출력 뜻 | 부호 있는 각도 / 90 (+ = 위쪽이 오른쪽으로 기움, T103과 같은 규약). 그래프 안에서 원본·좌우반전을 함께 돌려 sign((reg원본 − reg반전)/2) × (ord원본 + ord반전)/2 를 낸다 = CV 판정 점수와 같은 식 |
| 전처리 | 화면 방향 프레임(센서 -90° 회전 후 세로) **전체**를 224×224로 축소(크롭 없음, `AngleEstimator.cropRatio` = 1.0) → RGB/255 → 평균 [0.485,0.456,0.406], 표준편차 [0.229,0.224,0.225] → NCHW |
| 앱 문턱(출력 각도) | 약 ≥ 8.5°, 강 ≥ 29° (전체 CV 예측으로 고름; fold별 8.5~9.5 / 28~29.5). 최종 모델 출력으로 다시 고른 7.0 / 27.5는 학습 데이터에 맞춘 값이라 쓰지 않는다 |
| 앱이 하면 안 되는 것 | 원본·반전 출력을 따로 평균. `fullbw224_ord_reg.onnx` 두 번 평균은 1,331장 중 194장 값이 달라지고 T150 판정 미달(81/72/80, 강→직진 2.0%) |
| 점검 | ONNX vs PyTorch 최대 차 0.00003°; 최종 vs CV(그 사진을 안 본 fold 모델) 60장 평균 차 2.6°, 부호 일치 97%, 단계 일치 88% (`train/t159_check_final.py`) |
